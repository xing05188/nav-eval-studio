## 三、两个与最初设想不同的地方（避免后人踩坑）

1. **没有 `pathfinder.find_path(start, end)` 这个重载**。本机这版 habitat_sim 只暴露
   `find_path(ShortestPath)`，要构造 `habitat_sim.ShortestPath()`、填 `requested_start/requested_end`，
   再读 `points` 与 `geodesic_distance`（跨岛时是 `inf`）。
2. **官方 `ShortestPathFollower` 用不了**：它需要 `Env.get_agent_state()`（我们只有 `Simulator`），
   而且内部按 25° 转向，与这里的 15° 离散动作对不上。所以 oracle 按同样思路自己实现：
   取路径上第一个 > 0.3 m 的点，偏差 > 8° 就转，否则前进。

顺带发现并修掉一个老 bug：俯视图的 yaw 约定是镜像的（实测 `yaw=150°` 前进时
`Δx=-0.125, Δz=+0.217`，即前方 = `(-sinθ, -cosθ)`），原来狗头与起点箭头会把"左转"画成"右转"。

## 五、9 / 10 的落地要点（2026-11）

### #9 第三视角画中画

- `scene._chase_sensor_spec()`：`uuid="chase_rgb"`、320×240、`hfov=90`，位置 `[0, 2.6, 2.6]`
  （前进方向是 -Z，所以 +Z 在狗身后）。
- **`SensorSpec.orientation` 是 3 维欧拉角（弧度，agent 局部坐标），不是四元数**：
  塞 `[x,y,z,w]` 会直接 `TypeError`；实测 `[-0.6, 0, 0]` 俯视约 34°，`[0,0,0]` 是平视天花板。
- 合成在 `engine._draw_pip()`：贴第一视角右上角（HUD 在左下角，互不遮挡），带 1 px 边框与
  `3rd view` 角标。渲染开销实测：默认 15 fps 上限下开/不开都是 **14.4 fps**；
  解除上限后 55 vs 50 fps，差异落在噪声内——所以 `sim.pip` 默认 `true`。
- 开关语义：`sim.pip` 决定会话启动时**建不建**第二路相机；页面上的「画中画」开关
  （`POST /api/sim/pip`）只切显隐，不省那一次渲染，要省必须在启动前关配置。
- 机位从最初的 `[0,2.6,2.6]`/俯 34° 调近到 **`[0,1.8,2.0]`/俯 26°**：Go2 尺寸的物体
  在画中画里从 15×28 px 变成 20×40 px，再近就看不到前方场景了。

### 机器狗模型（#9 的延伸）

- 资产：`backend/app/services/sim/assets/go2/go2.glb`（8 MB / 399k 面）+ 同名
  `.object_config.json`，由 `go2_description` 的 URDF **离线烘成单个 GLB**
  （转换脚本同目录：`build_from_urdf.py`，需要临时装 trimesh + pycollada）。
  约定：Y-up、脚底在 y=0、车头朝 -Z，站姿用 Unitree 的 `hip 0 / thigh 0.9 / calf -1.8`。
- 运行时：`scene.add_robot()` 用 `get_object_template_manager().load_configs()` +
  `add_object_by_template_handle()` 挂成静态刚体，**必须** `motion_type=KINEMATIC`、
  `collidable=False`，否则狗会掉地上、还会挡住 agent 走路。
- 跟随：`engine._sync_robot()` 每帧把 agent 的 `position/rotation` 抄给模型。狗和 agent
  之间没有相对运动，所以不需要插值，也不建 bullet 多体、不跑关节求解。
- 显隐：habitat 这个版本没暴露 `SceneNode.visible`，隐藏是把模型挪到 `y=-1000`
  （`ROBOT_HIDDEN_Y`）。开关走 `POST /api/sim/robot`，配置项 `sim.robot_mesh`
  （`go2` / 空 / 自定义 `.object_config.json` 路径）、`sim.robot_scale`、`sim.robot_yaw_deg`。
- **不影响模型输入**：头部相机在 1.25 m、半垂直 FOV 36.9°，狗最高 0.38 m 且就在脚下，
  需要向前伸出 1.1 m 才可能进视锥，实际进不去；动作也只有 forward/left/right，不会低头看。
  所以加狗之后 VLN 的评测口径不变。
- 开销：399k 面走同一趟渲染，实测 57 vs 51 fps（噪声内），默认 15 fps 上限下无差别。

### #10 会话导出 mp4

三段流水线，谁都不挡谁（`services/sim/recording.py`）：

1. `FrameRecorder.push(jpeg)`（引擎线程）：按 `record_fps`（默认 10）做时间抽样后
   `put_nowait`，队列满（32 帧）直接丢帧——宁可少几帧，也不能让写盘拖慢渲染；
2. 写盘线程：落成 `000001.jpg` 递增序列，`close()` 把队列排空再退出；
3. `Mp4Export.start()`（后台线程）：`cv2.VideoWriter` + `mp4v` 按 10 fps 编码，
   先写 `*.part.mp4` 再原子替换，前端不会拿到半截文件。

- 落盘用 JPEG 不用原始 RGB：1120×480 的帧原始 1.6 MB，JPEG 约 80 KB，
  10 fps 约 48 MB/分钟；`record_max_frames` 默认 6000（10 分钟）封顶，超出丢帧。
- 目录轮转：`<work_dir>/sim/<session_id>/{frames,sim-<session_id>.mp4}`，
  只保留最近 5 局（`RECORD_KEEP_SESSIONS`），换局时顺手 `rmtree` 旧的。
- 停会话后仍可导出：引擎线程退出前已把队列写空，会话把目录与帧数留在 `_last_record`。
- 接口：`POST /api/sim/recordings/export`（启动编码）、`GET /api/sim/recordings/export`
  （状态）、`GET /api/sim/recordings/export/file`（下载，走 `?token=`）。
  页面不额外轮询，进度就在 `GET /api/sim/state` 的 `recording.export` 里。
- 实测：34 帧（约 3.4 s）→ 325 KB mp4，解码回来 34 帧、1120×480。
