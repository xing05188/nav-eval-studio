# 01 需求与功能清单

## 1. 目标用户

| 角色 | 典型诉求 | 权限 |
| --- | --- | --- |
| 算法工程师（operator） | 配置并提交评测、看指标、定位失败 episode | 读写任务与数据，不能删除用户 |
| 研究负责人（admin） | 管理模型档案、数据集、用户、系统设置 | 全部 |
| 评审/答辩演示（viewer） | 只看结果、回放与报告 | 只读 |

单机部署，默认为 admin，登录后可创建其他账号。保留角色体系的目的：体现完整的权限与审计设计，且答辩时可演示多角色视角。

## 2. 核心使用流程

```
登记数据集 → 生成切分 → 登记模型 → 新建评测任务 →
实时监控 → 查看指标对比 → 回放失败轨迹 → 导出报告
```

三条主链路必须能离线走通（MockAdapter + 内置示例结果）：

- 链路 A：数据集 → 观测时间轴 → 质量校验 → 导出因果切片
- 链路 B：任务创建 → 排队 → 运行 → 完成 → 指标对比 → 显著性
- 链路 C：结果 → 失败归因 → 轨迹回放（含记忆/几何叠加）→ 报告导出

## 4. 非功能需求

| 项 | 要求 |
| --- | --- |
| 启动 | `python run.py` 单命令，30 秒内可访问，无需数据库安装 |
| 前端 | Chrome/Edge 近两年版本，1440×900 及以上分辨率无横向滚动 |
| 性能 | 1000 条 episode 的指标聚合 < 1s；回放帧切换 < 100ms |
| 并发 | 单机最多 2 个评测任务并行（可配置），队列长度不限 |
| 可复现 | 任务记录 seed、配置文件、代码入口、环境快照 |
| 容错 | 子进程崩溃不拖垮服务；日志落盘；失败 episode 标记而非中断全任务 |
| 安全 | 口令加盐哈希，接口鉴权，路径参数白名单校验防目录穿越 |

## 5. 明确不做

- 不做模型训练、微调、数据增强。
- 不内嵌、不分发数据集与模型权重。
- 不实现 Habitat 渲染与物理仿真，只消费其输出。
- 不做多机分布式调度（保留扩展点）。
- 不做真实机器人实时控制（`engines/` 只留适配占位）。
