# 06 开发计划

## 1. 里程碑

| 阶段 | 内容 | 产出 | 预估 |
| --- | --- | --- | --- |
| M1 骨架 | 建库、种子、登录鉴权、统一响应、静态托管、`run.py` | 可登录的空壳系统 | 3 天 |
| M2 数据域 | 数据集登记/扫描、episode 检索、切分生成、质量校验、观测时间轴 | 数据子系统的完整界面 | 5 天 |
| M3 任务域 | 模板与模型档案、任务创建、调度器、SSE 监控、取消/暂停/重试 | 能跑通 Mock 全流程 | 6 天 |
| M4 分析域 | 指标聚合、对比矩阵、消融、bootstrap、失败归因、长时曲线 | 分析页面可出图 | 4 天 |
| M5 回放 | 逐帧元数据落盘、回放接口、Canvas 工作台、记忆与几何叠加 | 四区联动回放 | 5 天 |
| M6 报告与系统 | 报告生成（md/csv/pdf）、系统设置、用户、审计、状态页 | 全部 P0/P1 功能 | 4 天 |
| M7 收尾 | 打包、示例结果、截图、说明书配图、软著材料 | 可交付版本 + 材料 | 3 天 |

合计约 30 个工作日，可穿插毕设实验。

## 2. 验收判据

功能验收（离线模式，无 GPU、无数据集）：

1. 首次启动自动建库，30 秒内可登录。
2. 登记内置示例数据集并扫描，episode 列表可检索、可看观测时间轴。
3. 生成 smoke 切分，导出因果切片，文件中不存在晚于截止步的帧。
4. 用 Mock 模型创建任务，5 分钟内跑完 20 条，监控页进度、日志、资源曲线正常刷新。
5. 任务完成后指标非空，可对比两个任务，差值列正确。
6. 失败 episode 能自动归因，回放页四区联动，拖动时间轴同步刷新。
7. 导出 PDF 报告，图表与指标表齐全。
8. 审计日志记录上述关键操作。

技术验收：

- 因果性校验可被故意违规配置触发（提交返回 1006）。
- 任务取消后子进程确实退出，无残留进程。
- 服务重启后遗留 running 任务被正确标记。
- 全部单元测试通过，`metrics`、`split`、`causal_guard` 覆盖率不低于 70%。

软著验收：

- 源程序 ≥3000 行有效代码，前 30 页 + 后 30 页可导出。
- 说明书正文与截图一一对应，图号连续。
- 名称、版本、功能描述在申请表与说明书、代码页眉三处一致。

## 3. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 真实推理环境不可用 | 无法演示真实结果 | 全程保证 Mock 模式可用，真实模式作为可选 |
| 前端回放性能不足 | 帧切换卡顿 | 帧图按需加载 + 预取相邻 3 帧 + 缩略图 |
| SSE 在代理后失效 | 监控页无更新 | 提供轮询降级（`?fallback=poll`） |
| SQLite 并发写 | 任务写入阻塞 | WAL + 单写线程 + 批量提交 |
| 报告中文乱码 | PDF 不可用 | 使用 ReportLab 内置 CID 字体 STSong-Light |
| 代码量不足 | 软著被要求补正 | P1 功能按计划落地，前端组件与工具函数计入 |

## 4. 材料准备顺序

1. 代码冻结 → 导出源代码文档（前 30 页 + 后 30 页，每页 50 行，页眉"具身导航多模态流式评测与诊断软件 V1.0"）。
2. 截图 → 说明书配图（对照附录 A）。
3. 说明书排版 → 与申请表字段核对。
4. 申请表填写 → 权利归属证明、身份材料。

## 5. 待确认事项

1. 软件全称是否采用"具身导航多模态流式评测与诊断软件"，简称"NavEval Studio"。
2. 是否需要真实接入 StreamVLN 推理（影响 M3/M5 工时与验收方式）。
3. 前端 UI 组件库是否采用 Element Plus（备选 Naive UI）。
4. 报告导出是否必须 PDF（若只需 Markdown/CSV 可省 1 天）。
