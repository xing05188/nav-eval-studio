说明：

- 与早期规划相比，实际落地时**没有** `engines/`、`scripts/`、`tests/` 三个目录：多卡评测由外部 `torchrun` 脚本承担，自动化测试尚未补齐（见 [todo.md](todo.md)）。
- `services/sim/` 是独立的仿真子系统，仅在该页按需懒加载 `habitat_sim`，缺失时其余功能不受影响。

## 2. 分层职责

| 层 | 职责 | 禁止 |
| --- | --- | --- |
| api | 参数校验、鉴权、调用 service、组装响应 | 写业务规则、直接拼 SQL |
| services | 业务规则、事务边界、子进程/线程编排 | 依赖 FastAPI 对象 |
| services/sim | 仿真引擎线程、会话状态、推流、录制；只通过 session 暴露给 api | 直接读写平台业务表（由 api 传入 db 会话） |
| adapters | 与外部推理后端交互，产出标准记录 | 写数据库 |
| models/schemas | 持久化映射与传输契约 | 包含业务逻辑 |
| frontend | 交互与展示 | 直接访问文件系统 |

## 4. 关键实现要点

### 4.1 调度器

- 单进程内 `asyncio.Queue` + `asyncio.Semaphore(max_parallel_tasks)`；`asyncio.to_thread` 承载阻塞的任务体。
- 适配器内部用 `subprocess.Popen(start_new_session=True)` 起外部进程，按行读 stdout 推日志，便于整组 SIGTERM。
- 逐条落库：每条 `EpisodeRecord` 到达即写 `task_episode` + `resource_sample`，同时落 `frames/<episode>.jsonl` 并回填 `traj_path`。
- 看门狗与异常：子进程非零退出且尾部含 `out of memory` 时抛「显存不足」，否则带退出码与尾日志抛错；服务重启后扫描 `running/preparing` 标失败。
- 暂停/取消：暂停在 episode 边界 (`ctx.pause_event`)，取消置 `cancel_event` 并由 `adapter.stop()` 杀进程组。

### 4.2 Adapter 协议

```python
class BaseAdapter:
    name: str
    allowed_inputs: set[str]

    def prepare(self) -> None: ...            # 校验路径、准备命令、建目录
    def run(self) -> Iterator[EpisodeRecord]: ...  # 边跑边 yield，支持取消
    def stop(self) -> None: ...               # 终止外部进程
    def finish(self) -> dict: ...             # 汇总（可空）
```

`EpisodeRecord` 统一字段：

```text
episode_key, scene_id, success, spl, ne, os, ndtw, tl, steps,
latencies[], gpu_mem_peak_mb, tokens_peak, ctx_len_peak, failure_reason,
frames[]  # 逐帧元数据，见 03 文档 §3.4
```

- `StreamVLNAdapter`：拼 `torchrun` 命令启动上游 `streamvln_eval.py`，按字节偏移增量 tail `raw/result.json`，逐条转 `EpisodeRecord`；命令里追加 `--dump_frames <run_dir>/raw/frames`，回读同目录逐帧文件；脚本不支持该开关时通过源码探测自动降级。
- `MockAdapter`：按 `sha256(episode_key + seed)` 生成可复现的成功率/时延/轨迹与逐帧元数据，供无 GPU 演示。

### 4.3 因果性校验

两层：

1. 静态：`config_json.allowed_inputs ⊆ model_profile.allowed_inputs`，且模板要求 `depth` 时数据集 `has_depth=1`。
2. 运行时：适配器只从 `RunContext` 拿当前 episode 的起点与参考路径，结果解析只读取已完成的 episode 行，不把未来帧回写。

### 4.4 回放实现

- 逐帧元数据落 `storage/runs/task-XXXXXX/frames/<episode_key>.jsonl`（每行一帧），路径登记在 `task_episode.traj_path`。
- 数据来源有两路，优先级一致：平台调度任务（适配器 `record.frames`）与外部导入任务的回退路径 `runs/task-XXXXXX/frames/<episode_key>.jsonl`。
- 回放接口只读文件：`geometry.trajectory` 取 `pose[0]/pose[2]`，`reference` 取 `episode.meta_json.reference_path`，`speed_series` 由相邻帧位移/时间差计算。
- 无原始 RGB 时按帧元数据生成 SVG 示意帧（动作箭头 + 步号 + 位姿 + 指令），保证离线验收。
- 记忆叠加：`frames[idx]` 中的 `window_len / slow_update / tokens_before_prune / tokens_after_prune / ctx_len` 直接驱动右侧记忆面板与曲线。

### 4.5 报告生成

- Markdown 用模板拼接：任务摘要、指标表、失败案例 top-N；CSV 输出逐条结果明细。
- 不引入 PDF 与绘图依赖，保持部署轻量；图表导出（A-09）仍为待办。

### 4.6 交互式仿真

- 引擎线程独占一个 `habitat_sim.Simulator`，渲染循环按 `render_hz`（无人看）/`stream_hz`（有人看）自适应；每帧只编码一次 JPEG，多观众共享字节。
- 会话线程安全：动作入队，引擎线程按 `tick_hz` 消费；`/state` 返回不可变快照。
- 模型驾驶在同一进程另起推理线程，与引擎通过动作队列解耦，显存不足自动回退手动。
- 录制采用「引擎线程 push → 写盘线程落 JPEG → 后台线程编码 mp4」三段流水线，队列满即丢帧，绝不阻塞渲染。
- 细节（线程模型、接口契约、踩坑记录）见 [07](07-交互式仿真页面设计.md)、[08](08-交互式仿真接入模型预测.md)、[09](09-仿真诊断能力扩展.md)。

### 4.7 启动与打包

```bash
python run.py --port 8080          # 首次自动建库+种子，前端 dist 存在则托管
```

前端构建：`cd frontend && npm run build`，后端运行时读取 `frontend/dist`，替换产物无需重启服务。
