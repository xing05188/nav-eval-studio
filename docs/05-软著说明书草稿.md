## 一、项目背景

视觉语言导航要求智能体依据自然语言指令，在连续感知环境中自主行走并到达目标，是具身智能连接语言理解、环境感知与机器人决策的关键任务。近年来，基于视频视觉语言模型的流式导航方法发展迅速：模型以连续 RGB 观测为输入，逐帧输出导航动作，并通过滑动窗口与慢更新记忆压缩历史信息，从而在有限上下文预算下处理长时间视频流。

然而，围绕这类模型的工程化评测仍停留在脚本阶段，存在四个突出问题。第一，评测入口分散：数据准备、切分生成、推理启动、指标统计各自为独立脚本，参数靠手工修改，实验之间难以对齐。第二，过程不可见：一次评测往往持续数小时，运行中只能查看滚动日志，无法观察进度、显存、上下文长度与单步延迟的变化。第三，结果不可诊断：命令行只输出汇总指标，失败 episode 的原因、轨迹形态、记忆窗口状态均需另行分析，长时导航中的退化难以定位。第四，复现成本高：配置未固化、随机种子未记录、中间结果未归档，同一实验换人重跑即出现偏差。

同时，多模态与时空记忆方向的实验需要成组对照：仅视觉、视觉加几何、视觉加几何加运动状态，配合固定窗口、滑动窗口、特征缓存、空间裁剪等记忆策略，形成十余组配置。若仍以脚本方式管理，配置漂移与结果错配几乎不可避免。

本软件面向上述需求，将连续环境视觉语言导航的评测工作组织为"数据与配置—任务调度—推理回放—分析诊断"的完整闭环，提供浏览器端的可视化管理界面与统一的服务接口。软件本身不训练模型、不分发数据集与权重，而是以适配器方式对接外部推理后端，对评测全过程进行登记、编排、监控与解析，使导航模型的对比实验具备可复现、可观测、可追溯的工程属性。

本软件适用于具身智能算法团队、高校实验室与机器人导航研发场景，可作为模型迭代过程中的常备评测工具，也可作为论文实验数据的采集与管理平台。

## 二、软件功能介绍

本软件以浏览器为主要使用界面，分为总览、数据与配置管理、评测任务调度、推理与回放、指标分析与诊断、系统管理六个功能区。

### 2.1 总览

首页汇总数据集、模型档案、评测任务的数量与状态，展示当前队列、今日完成任务、最近任务列表与主要指标趋势。用户可由此一键进入新建评测或打开最近一次回放。`【图1：系统首页总览】`

### 2.2 数据与配置管理

- 数据集登记：填写名称、版本、类型（R2R-CE、RxR-CE、自定义）、本地根路径与说明，软件记录路径与元信息，不复制数据。
- 数据集扫描：解析 episode 清单，统计场景数、指令条数、轨迹长度分布，校验关键文件是否存在，输出 ready / missing / invalid 状态。
- Episode 检索：按场景编号、指令关键词、指令长度、轨迹长度组合过滤，分页浏览。
- 多源观测时间轴：将 RGB、深度、位姿、动作按时间戳对齐展示，自动标出时间偏差超过阈值的区段。`【图2：多源观测时间轴】`
- 数据质量校验：检查缺帧、时间戳乱序、位姿跳变、深度全零、指令为空等问题，生成问题清单与涉及 episode 编号。
- 切分生成：按全集、冒烟集、子集三种方式生成切分，支持按场景分层抽样与固定随机种子，切分条件随记录保存，可复算。
- 因果切片导出：对选定 episode 导出严格 t 前缀的观测序列，导出前二次校验不含未来帧。
- 局部点云预览：由深度反投影生成俯视点云缩略图，用于确认几何输入的可用性。`【图3：局部点云与可通行区域预览】`
- 配置模板：预置"模态组合 × 记忆策略"的七组模板，供评测任务直接引用。

### 2.3 评测任务调度

- 任务创建：选择数据集、切分、模型档案与配置模板，覆盖窗口长度、慢更新间隔、裁剪比例、随机种子、并发数与 GPU 编号；提交时固化配置快照。`【图4：新建评测任务向导】`
- 因果性预检：校验配置声明的输入项是否在模型允许清单内，不满足则拒绝提交并提示具体字段。
- 任务队列：按优先级排队，限制并行任务数，同一 GPU 上的任务互斥。
- 实时监控：以事件流方式推送进度、当前 episode、资源采样与日志，页面同步绘制度、显存、延迟、上下文长度曲线。`【图5：任务运行监控】`
- 任务控制：支持取消、暂停、恢复与仅重跑失败项；暂停在 episode 边界生效，不产生半条轨迹。
- 断点续跑：每条 episode 结果独立落盘，异常退出后从最后完成位置继续。
- 资源采样：周期性记录显存峰值、单步延迟、上下文长度与 token 数，供后续开销分析。

### 2.4 推理与回放

- 模型档案：登记模型名称、家族、代码路径、权重路径、启动入口与默认参数，支持可用性探测并列出缺失项。
- 适配器接入：以统一接口对接外部推理后端，内置 StreamVLN 适配器与离线演示适配器。
- 逐步推理：在回放工作台按"下一步"推进单个 episode，观察动作输出与记忆状态变化。
- 轨迹回放：显示第一视角帧序列、俯视轨迹与参考路径、动作时间轴与指令分段高亮，支持拖动定位与倍速播放。`【图6：轨迹回放工作台】`
- 记忆窗口可视化：显示当前窗口帧数、慢记忆更新次数、裁剪前后 token 数与上下文长度曲线。`【图7：记忆窗口与空间裁剪可视化】`
- 几何叠加：叠加局部点云俯视、可通行区域掩膜以及线速度、角速度曲线。`【图8：几何与运动状态叠加】`

### 2.5 指标分析与诊断

- 指标计算：统计成功率、路径长度加权成功率、导航误差、 oracle 成功率、归一化动态时间规整、轨迹长度，支持按场景加权与宏平均、微平均。
- 任务看板：展示指标卡、成功失败分布、步数直方图与延迟分布。
- 多任务对比：选择多个任务生成指标矩阵，并给出相对基线的差值列。`【图9：多任务指标对比】`
- 消融矩阵：按"模态组合 × 记忆策略"聚合，输出对比表与柱状图。`【图10：消融实验矩阵】`
- 配对显著性检验：在同一 episode 集合上对两个任务做配对 bootstrap，给出均值差、95% 置信区间与显著性标记。
- 长时性能曲线：按步数或时长分桶统计成功率与导航误差，观察长程退化趋势。`【图11：长时性能曲线】`
- 失败归因：按超时、碰撞、偏离轨迹、原地打转、早停、目标不可达、解析错误、显存不足、未知九类自动归类，并可人工复核修正。
- 报告导出：生成含任务摘要、指标表、图表与典型失败案例的报告，支持 Markdown、CSV 与 PDF。`【图12：评测报告导出】`

### 2.6 系统管理

用户与角色管理、操作审计、系统设置、系统状态监测与数据备份。系统状态页显示磁盘占用、数据库大小、队列长度与 GPU 显存。`【图13：系统设置与状态】`

## 三、软件特性介绍

**一、评测流程闭环化。** 软件将此前分散在多个脚本中的环节收敛为统一流程，数据登记、切分生成、任务下发、过程监控、结果解析、报告导出在同一界面内完成，配置在提交时固化为快照，历史任务不因模板变更而失去解释依据。

**二、过程可观测。** 任务运行期间以事件流推送进度与资源采样，显存、延迟、上下文长度随时间的变化实时成图，长时评测不再依赖滚动日志判断健康度。`【图14：运行期资源曲线】`

**三、结果可诊断。** 除汇总指标外，软件保留每条 episode 的轨迹、动作序列、逐帧延迟与记忆窗口状态，支持从"指标下降"直接下钻到"哪一条、哪一步、为什么失败"，并可将失败原因人工修正后沉淀为案例库。

**四、离线可演示。** 软件内置离线演示适配器，读取预置结果即可完整走通建库、任务、监控、分析、回放、报告全流程，无需 GPU 与数据集，便于教学演示与功能验收。`【图15：离线演示模式】`

**五、模型无关与轻量部署。** 通过适配器协议对接不同推理后端，软件主体不依赖特定模型实现；数据库采用 SQLite，服务以单进程启动，前端构建产物由服务端托管，交付时仅需一条命令，无需额外安装数据库或消息中间件。

**六、因果性可验证。** 软件在配置层设置输入白名单，在运行层封装观测总线，只暴露当前时刻及以前的观测，越界访问立即中断任务并记录审计，从工程上保证评测不泄漏未来信息。`【图16：因果性校验与审计】`

**七、可复现。** 任务记录随机种子、配置快照、代码入口与运行环境摘要，切分保存生成条件，任意历史结果均可按记录复算。

## 四、软件运行环境

**硬件环境**：CPU 为 x86_64 或 ARM64 架构，内存不少于 8GB，磁盘剩余空间不少于 20GB。离线演示与结果分析模式无需 GPU；接入真实推理后端时，建议配备 NVIDIA GPU（显存 ≥24GB）及对应驱动与 CUDA 环境。

**软件环境**：操作系统支持 Windows 10/11、Ubuntu 20.04 及以上版本；运行环境为 Python 3.10 及以上，依赖 FastAPI、Uvicorn、SQLAlchemy、NumPy、Matplotlib、ReportLab；浏览器建议使用 Chrome、Edge 或 Firefox 近两年版本；接入真实推理时另需外部推理后端及其依赖（如 Habitat 仿真环境），由用户按后端文档自行安装。

**部署方式**：解压后执行 `python run.py --port 8080`，首次启动自动建库并写入种子数据，浏览器访问 `http://127.0.0.1:8080`。亦可仅启动服务端，通过局域网内其他机器的浏览器访问。

## 五、系统总结构

`【图17：系统总体架构图】`

本软件采用前后端分离、单机一体化部署的结构，由浏览器前端、接口服务层、业务服务层、适配器层、数据存储层与外部推理后端六部分组成。

浏览器前端负责页面渲染与交互，包括总览、数据管理、任务监控、分析对比、轨迹回放与系统设置六个页面组；页面通过 HTTP 接口获取数据，通过事件流接收任务运行状态，回放页面使用 Canvas 绘制轨迹与曲线，使用图像请求逐帧切换第一视角画面。

接口服务层基于 FastAPI 实现，承担路由分发、参数校验、身份认证与统一响应封装；对上传的路径参数执行白名单校验，防止越界访问。业务服务层包含数据扫描、切分生成、质量校验、任务编排、指标聚合、失败归因、回放解析与报告生成八个服务，是软件的业务核心。

适配器层位于业务服务层与外部推理后端之间，向上提供统一的准备、单步执行与汇总接口，向下负责生成后端配置、启动子进程、解析输出。软件内置两类适配器：面向 StreamVLN 等视频视觉语言导航模型的子进程适配器，以及用于离线演示的示例结果适配器。

数据存储层由 SQLite 数据库与工作目录组成。数据库保存数据集、切分、模型档案、任务、逐条结果、资源采样、产物索引、用户与审计等结构化信息；工作目录保存配置快照、运行日志、逐帧元数据、帧图像与报告文件。大文件不入库，仅登记路径与校验值。

外部推理后端属于本软件对接的支撑组件，负责实际的视觉语言推理与导航动作生成。本软件不实现模型训练与推理计算，只负责评测流程的组织、观测与解析。

`【图18：评测任务执行流程图】`

一次完整评测的执行过程如下：用户在前端选择数据集、切分、模型与配置模板并提交，服务端校验参数与因果性后写入任务记录并进入队列；调度器在并发额度与 GPU 互斥条件满足时取出任务，生成配置快照并启动适配器；适配器拉起子进程，逐条执行 episode，将进度、资源采样与日志以标准格式输出；服务端按行解析并写入数据库，同时向前端推送事件；任务结束后聚合指标、生成回放数据与报告索引，前端展示结果并支持对比与回放。

## 六、各子系统介绍

### 6.1 数据与配置管理子系统

该子系统解决"评测输入从哪来、是否可用、如何固定"的问题。数据集以登记方式纳入管理，软件保存名称、版本、类型与本地路径，扫描时解析 episode 清单并写入索引表，形成可按场景、指令长度、轨迹长度检索的数据视图。`【图19：数据集登记与扫描】`

多源观测时间轴是本子系统的核心界面。软件以 episode 为单位读取 RGB 帧序列、深度帧序列、位姿记录与动作序列，按时间戳对齐后以横向时间轴呈现，偏差超过阈值的区段以醒目颜色标出，用户可直接定位到具体帧确认传感器同步情况。`【图20：数据质量校验结果】`

切分生成支持三种方式：全集直接引用原始划分；冒烟集按固定数量与随机种子抽取，用于快速验证流程；子集按场景分层抽样，保证场景覆盖。生成条件与随机种子随切分记录保存，任何切分均可复算。因果切片导出的处理流程为：读取 episode 观测序列，按时间顺序截取至指定步，剔除晚于该步的帧与位姿，再次校验后写出 jsonl 文件，确保下游使用时不引入未来信息。

### 6.2 评测任务调度子系统

该子系统负责将一次评测从"配置"变为"可执行、可观察、可控制"的任务。任务创建以向导方式组织，用户依次选择数据集与切分、模型档案、配置模板，再覆盖关键参数；提交时软件将模板参数与覆盖项合并为配置快照写入任务记录，此后模板变更不影响该任务。

调度器维护待执行队列，按优先级排序，并以并发额度控制同时运行的任务数；对于声明了 GPU 需求的任务，同一编号的 GPU 同时只允许一个任务占用。任务启动时生成工作目录，写入配置快照与启动命令，拉起子进程并记录进程号。

运行期监控通过事件流实现。服务端将进度、资源采样与日志三类事件推送给前端，前端分别更新进度条、绘制资源曲线、滚动日志面板。进度事件按固定间隔节流，避免高频刷新影响页面性能；日志同时落盘，页面刷新后可继续查看。

任务控制包括取消、暂停、恢复与重试。取消时向子进程发送终止信号，超时未退出则强制结束；暂停在 episode 边界生效，保证不产生半条轨迹；恢复重新进入队列；重试仅针对失败 episode 重新执行，已完成结果保留。`【图21：任务队列与控制】`

### 6.3 推理与回放子系统

该子系统负责与外部推理后端交互，并把推理过程还原为可观察的画面。模型档案记录代码路径、权重路径与启动入口，可用性探测检查路径是否存在、权重文件是否完整、GPU 是否可用、依赖是否满足，逐项给出结论与建议。

适配器以统一接口封装差异：准备阶段校验路径、生成后端配置、创建输出目录；执行阶段按 episode 逐一调用后端并收集标准记录；汇总阶段统计指标并落盘。子进程适配器将配置写入临时文件，按约定命令启动后端，解析其输出目录中的结果文件与帧图像；离线演示适配器直接读取预置结果，按种子加入可复现的微小扰动，用于无 GPU 环境下的功能演示。`【图22：适配器调用关系】`

回放工作台是本软件展示能力最集中的界面，由四个区域组成：左侧为俯视轨迹视图，绘制参考路径、实际轨迹、起点终点与当前位置；中部为第一视角画面，可叠加可通行区域掩膜与局部点云；下方为时间轴播放器，显示动作序列并支持拖动、单步与倍速；右侧为记忆状态面板，显示当前窗口帧数、慢记忆更新标记、裁剪前后 token 数与上下文长度曲线。用户拖动时间轴时，四个区域同步刷新，可直观看到"某一步动作之后，记忆窗口发生了什么变化"。`【图23：回放工作台四区联动】`

### 6.4 指标分析与诊断子系统

该子系统的目标是把"一个数字"变成"可解释的结论"。指标聚合按任务读取逐条结果，计算成功率、路径长度加权成功率、导航误差、oracle 成功率、归一化动态时间规整与平均轨迹长度，并同时给出宏平均与微平均。

多任务对比将所选任务组成矩阵，行表示任务，列表示指标，并允许指定基线任务生成差值列；消融矩阵进一步按"模态组合 × 记忆策略"两维聚合，直接对应实验设计中的对照关系。配对显著性检验在同一 episode 集合上对两个任务逐条配对，重采样计算均值差的置信区间，避免不同切分导致的不可比。`【图24：配对 bootstrap 结果】`

失败归因按规则执行：轨迹超出步数上限记为超时；与场景碰撞或位移异常记为碰撞；终点距离参考路径超过阈值记为偏离轨迹；连续多步位置变化小于阈值记为原地打转；模型提前输出停止动作但未达目标记为早停；终点不可达记为不可达；动作解析失败、显存不足分别单独归类。人工复核可覆盖自动结论，修改记录同时写入审计。长时性能曲线按步数分桶统计，用于观察随步数增加的成功率衰减，是评价记忆机制有效性的直接依据。

### 6.5 系统管理与权限子系统

该子系统提供用户、角色、审计与运行参数管理。软件定义管理员、操作员、访客三种角色，分别对应全部权限、读写任务与数据、只读查看。口令采用加盐哈希存储，登录后签发有时效的访问令牌。审计日志记录登录、任务创建与取消、数据删除、配置修改等关键操作，包含操作者、对象、时间与详情，支持按时间与操作类型检索。

系统设置包含工作目录、并发任务数、GPU 列表、结果保留天数与演示模式开关；系统状态页汇总磁盘占用、数据库大小、队列长度与 GPU 显存，便于在长时间评测前确认资源。`【图25：审计日志】`

## 七、结语

本软件将连续环境视觉语言导航的评测工作从脚本拼接提升为可视化、可复现、可诊断的工程流程，覆盖数据准备、任务编排、过程监控、结果分析与轨迹回放六个环节，并通过适配器机制与因果性校验保证模型无关性与评测严谨性。软件已在离线演示模式下完整验证全部功能链路，可支撑多模态流式导航方法在不同模态组合与记忆策略下的系统性对比实验。
