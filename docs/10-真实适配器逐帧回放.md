# 10 真实适配器逐帧回放

> 记录一次跨仓库改动：让"平台调度的真实 StreamVLN 任务"也能产出逐帧元数据，从而在回放工作台看到轨迹、动作、时延与记忆状态，而不只是汇总指标。
> 实施日期：2026-11-09。涉及仓库：`nav-eval-studio`（平台侧）与 `StreamVLN-kaggle-backup`（上游评测脚本）。

## 1. 问题

平台原有两条回放数据来源：

| 来源 | 逐帧元数据 | 结果 |
| --- | --- | --- |
| `MockAdapter` | 自行生成 `frames[]` | 回放完整，但只是演示数据 |
| 备份库导入的历史结果 | 无 | 解读 `result.json`，`task_episode.traj_path` 为空 |
| `StreamVLNAdapter`（平台调度真实任务） | **无** | `frames[]` 为空，回放只剩汇总指标与参考路径 |

根因不在平台解析，而在上游：`streamvln/streamvln_eval.py` 写出的 `result.json` 每行只有 episode 级字段

```text
scene_id / episode_id / success / spl / os / ne / steps / elapsed_s /
peak_gpu_mem_mb / mean_prompt_tokens / mean_memory_tokens_before|after /
cost_* / spatial_* / episode_instruction
```

`pose_list`、`action_seq`、逐帧时延只存在于进程内存，随 episode 结束即丢。平台侧 `EpisodeRecord.frames` 因此永远为空，
调度器仅当 `record.frames` 非空时才落 `frames/<episode_key>.jsonl` 并回填 `traj_path`。

## 2. 目标与约束

目标：真实任务跑完后，回放工作台能像 Mock 一样给出俯视轨迹、动作时间轴、逐步时延与记忆曲线。

约束：

1. **不改变评测口径**：新增的落盘不得影响动作选择、prompt 内容与指标计算；`--dump_frames` 缺省为空（不落盘），保证与旧行为逐字节一致。
2. **不破坏旧环境**：上游脚本可能没有这个开关，平台不能因为多传参数而失败。
3. **字段形状唯一**：上游写什么、平台读什么、前端渲染什么，三者共用一份契约，避免出现第二套命名。
4. **写盘不拖慢推理**：每步只追加一行 JSON 并 flush，不做目录扫描与聚合。

## 3. 字段契约

`frames/<scene_id>_<episode_id>.jsonl`，每行一帧，字段与 `replay_service._read_frames` 完全对齐：

| 字段 | 类型 | 上游取值 |
| --- | --- | --- |
| `idx` | int | `step_id`（episode 内从 0 递增） |
| `t` | float | `perf_counter() - episode_start`（秒） |
| `pose` | [x,y,z] | `agent_state.position`（Habitat 世界坐标，与 `reference_path` 同系） |
| `yaw` | float | `agent_state.rotation` 四元数按项目口径换算的弧度 |
| `action` | string | `0 STOP / 1 forward / 2 left / 3 right` 翻译后的字符串 |
| `latency_ms` | float | 入帧到出动作的决策耗时（含预处理与前向，不含 `env.step`） |
| `window_len` | int | 本次前向实际拼入的视觉槽位数（当前帧 + 历史帧） |
| `slow_update` | bool | `step_id % num_frames == 0`（历史重采样 / 模型重置那一步） |
| `tokens_before_prune` | int | 模型 `last_prune_stats["total"]`（未启剪枝为 0） |
| `tokens_after_prune` | int | `last_prune_stats["kept"]`（未启剪枝同上） |
| `ctx_len` | int | 最近一次前向的 prompt token 数 |

平台侧在读入时再规整一次：丢弃 `pose` 不足 3 维的行、按 `idx` 排序、上限 600 帧（与 `replay_service.MAX_FRAMES` 一致）、
缺字段给默认值；随后把整个列表放进 `EpisodeRecord.frames`，由调度器原样落盘到
`storage/runs/task-XXXXXX/frames/<episode_key>.jsonl` 并登记 `task_episode.traj_path`。

## 4. 上游改动（StreamVLN）

### 4.1 新增 `streamvln/replay_frames.py`

只依赖标准库的写入器，便于在没有 habitat/torch 的环境里单测：

```python
writer = EpisodeFrameWriter(frames_dir, scene_id, episode_id)   # frames_dir 为空则空操作
writer.write(idx=..., t=..., pose=..., yaw=..., action=..., latency_ms=...,
             window_len=..., slow_update=..., tokens_before_prune=...,
             tokens_after_prune=..., ctx_len=...)
writer.close()
```

- 文件名 `<scene_id>_<episode_id>.jsonl`，八字幕唯一，多卡并行不会互相覆盖；
- 以 `"w"` 打开（每集只跑一次，断点续跑按 `done_res` 跳过），避免重跑把两轮帧拼在一起；
- 每行 `flush()`，异常中断时最多丢最后一行。

### 4.2 `streamvln_eval.py` 的接入点

| 位置 | 改动 |
| --- | --- |
| 参数表 | 新增 `--dump_frames <dir>`，默认 `''`（不落盘） |
| `__init__` | `self.frames_dir = args.dump_frames or ""` |
| episode 开始 | 建写入器，初始化 `window_len / tokens_before / tokens_after` 缓存 |
| 前向分支 | 记录本次视觉槽位数；剪枝统计写缓存 |
| 动作确定后 | 写一帧（此时位姿、动作、时延、ctx 都已就绪） |
| while 结束 | 立即 `close()`，**早于** `result.json` 那一行落盘 |

最后一条很关键：适配器是在读到 `result.json` 新行时才转记录的，先关闭文件才能保证读到的是完整文件。

实现细节：

- 位姿用 `agent_state.position`（世界坐标），而不是把相机坐标再变换一遍，保证与数据集 `reference_path` 同一坐标系；
- 朝向用 `agent_state.rotation` 四元数按 `yaw = atan2(2(wy+xz), 1-2(y²+z²))` 换算，与平台导入 episode 时计算 `yaw` 的公式一致；
- `slow_update` 取 `step_id % num_frames == 0`，与"历史帧重采样 + 模型重置"的代码分支对应；
- 未开 `--prune_mode voxel` 时模型不产出 `last_prune_stats`，此时两个 token 字段写 0，而不是伪造数值。

## 5. 平台改动（nav-eval-studio）

`backend/app/adapters/streamvln_adapter.py`：

| 改动 | 说明 |
| --- | --- |
| `_supports_frame_dump(script)` | 读上游脚本源码探测是否存在 `--dump_frames`，老版本自动降级并写日志 |
| `prepare()` | 检测通过则 `replay_dir = run_dir/raw/frames` |
| `_build_command()` | 追加 `--dump_frames <replay_dir>`；放在 `extra_args` 之前，用户自定义参数仍可覆盖 |
| `_load_frames(scene_id, key)` | 读 `<scene>_<episode>.jsonl`，规整成统一形状；找不到时按 `*_<episode>.jsonl` 兜底 |
| `_to_record()` | 填 `frames`；`latencies` 改为逐帧真实时延；`tokens_peak / ctx_len_peak` 用逐帧峰值，缺失时才退回 episode 级均值 |
| 兜底命名 | `MAX_REPLAY_FRAMES = 600`，与回放服务一致 |

同时修掉三处旧映射问题：

1. `tokens_peak = mean_prompt_tokens * 100` 是凭空放大 100 倍的伪造值，已删除；
2. `latencies` 只有一个"episode 平均单步时延"采样，导致 `latency_p95_ms` 恒等于均值，现改为逐帧时延；
3. `ctx_len_peak` 原来固定为 0，现取逐帧 `ctx_len` 最大值。

## 6. 降级与容错

| 场景 | 行为 |
| --- | --- |
| 上游脚本无 `--dump_frames` | 不传该参数，日志提示"本次不产出逐帧回放数据"，回放只显示汇总 + 参考路径 |
| 逐帧目录/文件缺失 | `frames = []`，其余指标照常入库 |
| 行被截断 / JSON 非法 | 跳过该行（与 `result.json` 的容错策略一致） |
| `pose` 不足 3 维 | 丢弃该帧，避免前端画出 0 点轨迹 |
| 帧数过多 | 截断到 600 帧（前端一次渲染的上限） |
| 未启剪枝 | `tokens_before/after` 为 0，回放不显示裁剪事件 |

## 8. 运维说明

- **开启/关闭**：平台侧无需配置，自动探测；想临时关闭可在任务 `adapter.extra_args` 里覆盖（同名参数取后者）。
- **产物位置**：上游 `<run>/raw/frames/*.jsonl`；平台 `<work_dir>/runs/task-XXXXXX/frames/<episode>.jsonl`（回放读这份）。
- **导入任务**：从历史产物导入时（`config_json.source_dir` 指向实验目录），导入会按
  `<scene_id>_<episode_id>.jsonl` 把 `<实验目录>/replay_frames/`（或 `frames/`、`raw/frames/`）的逐帧文件
  复制到 `runs/task-XXXXXX/frames/` 并写 `task_episode.traj_path`。旧任务未复制也能回放：
  `replay_service._frames_file()` 会按 `traj_path` → 任务 `frames/` → `raw/frames/` → 导入源目录逐级兜底。
- **排查**：回放页出现"该 episode 没有逐帧元数据"提示时，先看任务日志是否有"评测脚本不支持 --dump_frames"，
  再确认 `<work_dir>/runs/task-XXXXXX/frames/` 是否有文件、`task_episode.traj_path` 是否非空，
  以及实验目录下是否真的存在与 `(<scene_id>, <episode_id>)` 同名的 `replay_frames/*.jsonl`。

## 9. 后续可做

1. **第一视角真图落盘**：当前 `frame/{idx}` 在无原始 RGB 时返回示意帧 SVG；可在上游按 `frame_interval` 存 JPEG（磁盘换真实感，10 fps 约 48 MB/分钟，需要限额）。
2. **episode 级元数据**：把 `cost_*`、`spatial_*`、`mean_memory_tokens_*` 一并落 jsonl 头部行，回放右侧面板可直接展示成本归因。
3. **裁剪记账常态化**：未开剪枝时用 `ctx_len` 近似 memory token，让"裁剪前后"始终有数可看（需明确口径，避免误导）。
4. **原子性**：写 `.part` 再改名，避免极端情况下回放读到半截文件（当前按行容错，影响已很小）。
